# بازتولید و بایگانی

Python 3.12 برای بازتولید مطالعه آزموده شده است. نسخهٔ Z3 نصب‌شده، پکیج‌های تحلیل، سیستم‌عامل، CPU، حافظهٔ میزبان، سقف‌های cgroup، seed و بودجه در `results/final/environment.json` ثبت می‌شوند. شناسهٔ Git مربوط به کد اجرا و هش SHA-256 ماژول‌ها و ورودی‌ها در همین فایل‌اند. در بستهٔ ZIP، نبود پوشهٔ `.git` فقط روی ثبت commit اجرای تازه اثر می‌گذارد. نسخهٔ شواهد همراه با خروجی ثبت شده است.

```bash
bash setup.sh
bash scripts/run_project.sh demo
bash scripts/run_project.sh test
bash scripts/run_project.sh pilot
bash scripts/run_project.sh full
```

مطالعه بعد از هر اجرا یک رکورد JSON اتمی می‌نویسد. اگر پردازش متوقف شود، همان دستور برای همان مقصد و روی مشخصات سازگار ادامه می‌یابد. برای اجرا در ماشینی با مشخصات متفاوت، مسیر تازه انتخاب کنید. `case_manifest.csv` هش ورودی هر مورد را دارد و `experiment_manifest.csv` اجرای برنامه‌ریزی‌شده را با شناسهٔ پایدار ثبت می‌کند. `logs/failures.csv` وضعیت اجراهای غیرموفق را نگه می‌دارد. پایان عادی یا وقفهٔ قابل دریافت، CSV را از رکوردها می‌سازد. در بستهٔ تحویل، CSV خام کامل همراه شواهد است و رکوردها را می‌توان با اجرای مجدد ساخت.

نوت‌بوک [FINAL_COLAB](../notebooks/FINAL_COLAB.ipynb) هم از ZIP استخراج‌شده و هم از شاخهٔ قابل دسترسی GitHub استفاده می‌کند. در نبود شاخهٔ منتشرشده، `TEAM3_PROJECT` را به مسیر نسخهٔ استخراج‌شده تنظیم کنید. اجرای گردش‌کار GitHub Actions برای شاخهٔ محلی پس از انتشار قابل مشاهده است.
