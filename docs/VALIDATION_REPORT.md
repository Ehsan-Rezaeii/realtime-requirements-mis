# اعتبارسنجی

۱. آزمون‌های واحد و یکپارچه وضعیت الگوها، افق، مشاهدهٔ ثابت، نام فعال‌ساز، MISهای چندگانه، خطا و resume را پوشش داده‌اند. متن اجرای واقعی در `results/validation/test_log.txt` است.

۲. هر MIS در worker با حل‌کنندهٔ تازه با همان مشاهدات کنترل می‌شود. این آزمون از مسیر حل و فعال‌سازی مستقل است و همچنان از رمزگذاری Z3 استفاده می‌کند. زمان آن جداگانه ثبت می‌شود.

۳. اعتبارسنج اصلی رد بولی را مستقیم در Python می‌سنجد و از API حل Z3 استفاده نمی‌کند. سیگنال‌ها را برحسب وابستگی میان قواعد به مؤلفه می‌شکند. قیدهای تک‌سیگنالی و مشاهدات، خانه‌های ثابت می‌سازند. ردهای شاهد ابتدا امتحان می‌شوند و برای خانه‌های آزادی که باقی بمانند، حداکثر ۲۰ بیت در هر مؤلفه کامل شمارش می‌شود. تعارض قطعی روی دادهٔ جزئی نیز قابل تشخیص است. اگر هیچ شاهد و دلیل قطعی پیدا نشود و حد شمارش عبور کند، وضعیت `not_checked` گزارش می‌شود.

۴. برای هر ورودی، نتیجهٔ کل، بردار دستهٔ RQ1 در صورت وجود، نتیجهٔ گزارش‌شدهٔ ابزار و هر MIS متمایز بررسی می‌شوند. برای تزریق، سازگاری پس‌زمینه و کمینگی هستهٔ مورد انتظار هم جدا کنترل می‌شود. اجرای timeout شاهد منطقی محسوب نمی‌شود. شمارش ردیف‌های مستقل به تعداد آزمون‌های منطقی دربارهٔ همان موارد اشاره دارد.

```bash
python scripts/validate_study.py --study results/final
```
